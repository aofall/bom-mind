# BOM Mind

将 Excel BOM 转换为可折叠、可追溯的产品结构图。支持 `.xls`、`.xlsx` 和 BOM Mind JSON 项目文件。

## 运行

Windows 可使用快速启动脚本：

```powershell
.\start.ps1
```

或使用 Node.js 22.x（至少 22.13）或 24+，配合 pnpm 11：

```text
pnpm install
pnpm dev
```

本地开发地址：`http://127.0.0.1:5173/`。构建生产文件后可部署到任意支持 HTTPS 的静态托管平台。

```text
pnpm test
pnpm build
pnpm preview
```

普通构建输出到 `dist/`，使用相对资源路径，适合通过 HTTP/HTTPS 部署或本地预览；仍使用 ES 模块，不用于直接双击 HTML。

如需不启动本地服务，直接打开文件：

```text
pnpm run build-legacy
```

构建后双击 `dist-legacy/index.html`，分发时保留整个 `dist-legacy/` 目录。此构建使用普通 IIFE 脚本和内联 Blob Worker，避免从 `file://` 加载 ES 模块及外部 Worker；不需要联网或安装 Node 即可使用已构建的工具。`legacy` 指本地文件加载方式，目标仍是现代 Chrome、Edge，不代表支持 IE。浏览器对本地文件的存储策略可能不同，重要项目请导出 JSON 备份。两种构建的输出目录互不覆盖。

## 使用

1. 选择完整的 Excel BOM，确认工作表、表头行与字段映射。
2. 搜索产品，查看结构图或文字树。点击节点查看原表数量、代码、规格、父项路径和源行号。
3. 可展开到指定层级、查找当前产品内的材料，并定位数据提示。
4. 导出 PNG、SVG、缩进文本，或 JSON 项目。JSON 包含全部产品，可重新导入恢复。
5. “记住项目”仅将项目保存在当前浏览器的 IndexedDB；关闭该选项可清除本地保存的最近项目。换设备需要原始 Excel 或导出的 JSON。
6. 产品目录使用虚拟滚动，可浏览全部产品。勾选产品后，“全选搜索结果”选择全部匹配项（包括未滚动到的产品），“选择全部产品”覆盖整个项目；搜索、滚动和切换产品保留已选项，导入新项目清空选择。
7. 点击“批量导出”可下载已选产品目录 CSV，或按产品生成完整 SVG、PNG、缩进文本并打成 ZIP。每包包含目录和成功/失败记录；按约 32 MiB 未压缩文件大小分包（单个文件不拆分），下载当前包后继续下一包，避免大量图片同时占用内存。取消后已下载的包仍可使用。JSON 仍是完整项目备份，不受产品勾选影响。
8. 画布工具栏的“排版设置”可实时调整节点宽度（200–600px）、自动加宽及上限、超宽文字处理方式、标题字号。默认自动换行、320px、14px；宽度可通过滑块或数值输入调整。画布与 SVG/PNG 共用排版逻辑，节点随内容增高，支持节点选择、展开收起、搜索定位、拖动与缩放。设置保存在本机浏览器，不改变原始 BOM 数据、文本或 JSON。
9. 单项和批量导出使用加宽的双栏面板：左侧为真实产品预览及尺寸，支持适应画布、实际大小和拖动缩放；右侧选择导出方式，也可直接调整排版。批量预览可搜索已选产品或逐项切换，尺寸随当前预览产品更新；仅计算当前产品，不预生成全部图片。生成 ZIP 时锁定本次排版。PNG 超过边长或像素限制时会整体缩小，需要完整清晰地查看大图时优先使用 SVG。
10. 画布工具栏的“节点详情”可展开或收起右侧面板，标题右侧也可收起。桌面首次默认展开，手动选择会保存在本机；收起后画布获得完整的侧栏宽度。选中节点、搜索定位和切换产品不会强制展开，查看异常明细会主动打开。小屏幕使用覆盖式抽屉，可通过关闭按钮、遮罩或 Escape 关闭，不改变桌面偏好。
11. “组合表”按原始层级分列、按末端分支排列，父节点纵向合并。同码材料在不同分支独立保留，产品根节点显示在表头；“—”表示无更深层材料，“…”表示下级已折叠。默认完整结构，也可切换到当前展开结构并复用展开层级、材料搜索和节点详情。表头固定，支持横向及纵向滚动，不限制为前 200 行。
12. “表格设置”可选择编码、规格、原表数量、来源行号，名称为必选；列宽为 180–600px、字号为 12/14/16px，设置保存在本机。“导出 Excel”使用与预览相同的合并范围、文字换行和行高，输出层级组合表、当前范围的节点明细及适用的异常记录。节点明细中的编码保持文本，空数量、0 与原始文本数量分别保留。材料文字顶端对齐，长文字自动增加高度；过高行拆成多个物理行并继续合并，超过 Excel 单元格长度限制时明确报错。
13. 全局导出面板可切换图像与 Excel 组合表预览；批量导出选择 Excel 后也可逐项预览，每个产品生成独立 `.xlsx`，沿用 ZIP 分包、进度及取消。ExcelJS 仅在导出 Worker 中加载，不进入 Web 首屏主包；离线构建内联所需 Worker，包含完整导出依赖，产物会相应增大。Excel 导出全程在本机执行。

## 层级规则

严格保留输入行序。层次 L 的节点只管理后面连续出现的更深层记录，遇到层次 ≤ L、产品代码变化或文件结束时结束。

- 产品代码用于创建层级 0 的产品根节点，原表 `.1` 为其直接子项。
- `.1 → ..2 → ...3 → ..2` 中，最后的 2 回到第一个 1 下，与前面的 2 并列。
- 同码材料在不同位置分别建节点，不合并数量、不跨产品借用子树。
- 缺少父项、非法层次等结构错误不自动猜测。错误分支暂不挂接，遇到新的层次 1 后恢复，原始记录与问题仍保留在 JSON 中。
- 同产品代码在不连续区段再次出现时，分别建树并提示确认版本。

## 数据口径与隐私

Excel 在 Web Worker 中解析，文件内容不上传服务器。站点不接入外部 AI，不使用远程字体和分析脚本。演示数据为虚构数据，真实附件只在本地 `work/` 中用于测试，已排除在 Git 和站点构建资源之外。

数量仅按原表显示。空数量保留空值，不作为 0 或 1；尚未计算逐层乘积、损耗或跨单位汇总。末级节点仅表示本次导出没有提供更深层资料，不代表已经确认其属于原材料或外购件。

网站访问支持跨设备，当前版本不提供云端项目同步、多人共享、单位换算、版本比较或离线 PWA。首次访问需要网络。

## 项目结构

```text
src/core/parser.ts       层级解析、字段识别、JSON 往返校验
src/core/export.ts       SVG / PNG / 文本导出
src/core/product-export.ts 单项与批量共用的产品文件生成
src/core/mapping.ts      字段映射计数与校验
src/core/storage.ts      浏览器本地保存
src/worker.ts            Excel 后台解析
src/components/          交互结构图
src/components/Modal.tsx 弹窗关闭、键盘与焦点管理
src/components/*Dialog.tsx 各导入、导出、异常和帮助弹窗
src/App.tsx              导入、检索、详情、异常和导出页面
tests/                  核心边界测试
scripts/check-real.ts   实际附件全量核对
docs/                   方案、使用及验证资料
work/                   实际测试数据、缓存与中间文件（不入库）
dist/                   生产静态文件（由构建生成）
```

实际附件存在 `work/实际BOM.xls` 时，运行 `pnpm test:real` 进行全量核对。该测试核对产品、明细、材料代码、材料层次、空数量，并独立检查全部父子关系和 JSON 往返。耗时包含独立校验，不代表浏览器导入耗时。

SheetJS 使用官方分发的 0.20.3 包；其他依赖以 `pnpm-lock.yaml` 锁定。正式升级依赖后应重新运行核心测试与实际附件检查。

## 代码格式

使用项目内的 Prettier 配置，缩进 2 个空格，建议行宽 100 个字符。每条逻辑语句独立成行，独立状态和变量分别声明；有多步操作的回调、条件分支及 JSX 结构分行展开。简短的提前返回或简单表达式可保持紧凑。长字符串、SVG 属性等不为满足行宽而改变其内容。

```text
pnpm format
pnpm format:check
```

格式化范围覆盖源码、测试、检查脚本、配置和项目说明，排除构建产物、第三方依赖、本地真实数据及工作目录。PowerShell 启动脚本手工保持多行结构，使用 4 个空格缩进。WebStorm 可选择本项目的 Prettier，并启用重新格式化或保存时运行；编辑器通用缩进规则由 `.editorconfig` 提供。

## 代码检查

Prettier 负责排版；ESLint 负责 TypeScript、React Hooks 和可维护性约束；Stylelint 使用错误检测规则，检查未知属性、无效值、重复声明及已废弃属性。不同组件共享 `span`、`svg`、`button` 等末级标签，优先级排序规则会把互不相关的组件也进行比较，因此有说明地关闭 `no-descending-specificity`，保留组件及响应式覆盖顺序。ESLint 通过 `eslint-config-prettier` 避免重复检查格式，仅额外保留独立变量声明、跨行分支花括号和每行最多一条语句等约束。

```text
pnpm check          # 格式、ESLint、Stylelint、TypeScript、单元测试
pnpm lint           # TypeScript / React 检查，警告也会阻止通过
pnpm lint:css       # CSS 检查
pnpm typecheck      # TypeScript 类型与未使用声明检查
pnpm lint:fix       # 修复 ESLint 可安全自动修复的问题
pnpm lint:css:fix   # 修复 Stylelint 可自动修复的问题
```

自动修复后运行 `pnpm format`，再运行 `pnpm check`。`tsconfig.json` 同时启用未使用局部声明和参数检查，因此 `build`、`build-legacy` 也会阻止残留的未使用 import。ESLint 的 Hooks 检查覆盖调用顺序及依赖数组；当前项目未启用 React Compiler，不额外启用编译器迁移规则。文件名过滤需要匹配 Windows 禁止的控制字符，保留这一处有说明的局部正则规则豁免。

提交前执行 `pnpm check`。GitHub Actions 配置位于 `.github/workflows/check.yml`，推送或创建拉取请求后使用 Node.js 24 和 `package.json` 锁定的 pnpm，依次执行锁文件安装、`pnpm check` 及两种构建。真实 BOM 仅在本地存在时执行 `pnpm test:real`，不上传到 CI。
